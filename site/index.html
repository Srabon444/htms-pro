HRMS Pro

A multi-tenant HR and payroll platform built to run a software company end to end: people, leave, attendance, payroll, meals, expenses, hiring and reviews, with every tenant's data fenced off inside Postgres itself.

What happens to one request

Isolation is enforced twice: once in application code and again in the database. A bug in a page or a forgotten filter still cannot read another tenant's rows, because the database connection itself is scoped before any query runs. Steps marked as a gate can stop the request.

  1. Security headers and request id

    Every response gets a CSP with frame-ancestors 'none', nosniff, a strict referrer policy, HSTS on HTTPS and an x-request-id that also lands in the structured logs.

  2. Body type checkGATE

    A form post whose body is not form data is answered with 415 before any action runs.

  3. Session lookup

    The cookie holds an opaque token. Only its SHA-256 hash is stored, so a leaked sessions table cannot be replayed.

  4. Rate limits in RedisGATE

    Per-user mutation limits, plus login limits per IP, per email and IP pair with exponential back-off, and step-up 2FA when one email is tried from several IPs. Sign-in limits fail closed if Redis is down.

  5. Tenant resolutionGATE

    The /t/<slug> path picks the tenant. The user must hold an active membership there, and tenants that require 2FA send holders of restricted permissions to enrol first.

  6. Permission and scope checkGATE

    Roles grant permissions at a scope: own, team, department or all. Services resolve the scope and filter rows by it; a row outside scope reads as not found.

  7. Scoped transaction

    withTenant opens a transaction as the hrms_app role, which has no BYPASSRLS, and sets app.tenant_id, app.user_id, app.employee_id and feature flags such as app.payroll_all with set_config.

  8. Row-level security in PostgresGATE

    A restrictive policy on every tenant table compares tenant_id to the session setting. Personal tables add an owner-row policy, so a payslip is visible only to its employee unless the payroll flag is on.

  9. Audit trigger

    Inserts, updates and deletes write who changed what. Sensitive columns such as salary go to a separate table readable only with an explicit flag, and the main log shows them masked.

  10. Side effects through the queue

    Mail, payslip and meal-bill delivery are queued in BullMQ and handled by the worker, so a slow SMTP server never holds a request open.

Architecture

Two Node processes share one codebase. The web app serves pages and form actions; the worker runs queued jobs and an hourly scheduler. Everything else is a managed dependency that Docker Compose brings up locally.

Three database roles

  • hrms_owner owns the tables and runs migrations only.
  • hrms_app carries all tenant traffic and is subject to every policy.
  • hrms_auth sees users, sessions and invitations, and accepts invitations through a security-definer function.

Worker and scheduler

  • Queues: mail, meal-bills, lifecycle.
  • Hourly run: exits and probation, leave accrual, attendance close-out, meal orders, overdue meal bills, candidate data purge. Each step runs on its own, so one failure does not stop the rest; a failed step is logged, counted in hrms_lifecycle_step_failures_total and retried with the job.
  • Both processes stop cleanly on SIGTERM.

Operations

  • /healthz and /readyz for the orchestrator.
  • /metrics in Prometheus format behind a bearer token.
  • Pino JSON logs with request ids; encryption keys rotate by key id.

Tenancy and security

Shared database, shared schema, tenant id on every row. Policies are generated in one migration pass for every table that has a tenant_id column, so a new table cannot be added without them.

The tenant policy, as generated

alter table public.leave_requests enable row level security;
alter table public.leave_requests force row level security;

create policy hrms_tenant on public.leave_requests
  as restrictive for all to hrms_app
  using (tenant_id = nullif(current_setting('app.tenant_id', true), '')::uuid)
  with check (tenant_id = nullif(current_setting('app.tenant_id', true), '')::uuid);

Account security

  • Argon2id password hashing and a password strength check that rejects passwords containing the email.
  • TOTP 2FA with recovery codes, an encrypted secret and replay protection on the last used step.
  • Optional Google sign-in, trusted devices and step-up verification.
  • Composite tenant foreign keys, so a row can never point at another tenant's parent.
  • Uploads are sniffed by content, not by extension, before they reach MinIO.
  • Retention settings purge old candidate data and audit rows per tenant.

Business requirements

The product exists so a growing software company in Bangladesh can stop running HR on spreadsheets and email threads, and so one deployment can serve several companies without their data ever meeting.

Goals

  • One place for the employee record, from offer letter to exit interview.
  • Payroll that a finance team can run, check and approve in an afternoon, with payslips emailed as PDFs.
  • Office meals ordered daily and billed monthly to each employee without manual tallying.
  • Approvals that follow the reporting line, with a clear inbox for every approver.
  • Evidence on demand: who changed a salary, when and from what.

Constraints

  • Money stored as whole minor units so totals never drift; each company picks its currency and every payroll run keeps the currency it was computed in; Bangladesh income tax slabs per tax year.
  • A new company starts on neutral settings (UTC, USD, January fiscal year, Saturday and Sunday off); the platform admin can set its time zone, currency, fiscal month and weekend days when creating it.
  • Names in Latin, Cyrillic, Greek, Vietnamese, Devanagari and Bengali script must render in generated PDFs.
  • Runs on plain Postgres, Redis and S3-compatible storage; no vendor lock-in.
  • A tenant can be onboarded by a platform admin in minutes, by invitation, and bring its existing records in from CSV files.
  • Branches in different countries keep attendance in their own time zone.
  • Usable on a phone: every list turns into labelled cards on small screens.

Who uses it

Owner

Holds every permission, configures the company and decides what HR and finance may grant.

HR admin

Hires, onboards, maintains records, runs leave and lifecycle, writes letters and policies.

Finance

Sets salaries, runs and approves payroll, pays expenses, settles meal bills and loans.

Line manager

Approves leave, attendance fixes and timesheets for the team, reviews performance.

Employee

Applies for leave, punches in, orders meals, claims expenses, reads payslips and policies.

Platform admin

Creates and suspends tenants from a separate console, behind 2FA; has no tenant data access unless invited.

Functional specification

Each module, what it lets people do, and the rules the server enforces regardless of what the browser sends.

Module Users can Rules enforced
Access Invite users, assign roles, edit custom roles in a permission matrix, read the audit log. Nobody grants a permission they lack; the owner role is locked; restricted permissions need 2FA when the tenant asks for it.
Employees Create, import by CSV, edit records and documents, add education and experience with certificates, manage departments and designations, request profile changes. Self-service edits go through an approval; codes are unique per tenant; history keeps every job change.
Leave Apply with an optional prescription or other file, cancel, approve and see balances as one card per leave type with the accrual rule and a running-balance history; earn comp-off for holiday work; import opening balances and holidays from CSV. Monthly accrual, carry-forward caps, holidays and weekends skipped, no overlapping requests, nobody approves their own.
Attendance Punch in and out, take breaks, request corrections with evidence, assign shifts and work weeks, see late and absent days, check punches against work sites, and punch at a shared kiosk with a code and PIN. Grace minutes per shift; each branch can set its own time zone and every day keeps the zone it was computed in, so a transfer never counts a punch twice; days close automatically each hour; corrections need a manager. A work week gives a person their own weekend, which attendance, leave days, payroll working days and meals follow; it never changes a month whose payroll is approved. Work sites match a punch by office network or by location inside a radius, and can flag or block punches elsewhere; unpaid breaks come off worked time. A paired kiosk takes punches by employee code and a personal PIN stored only as a keyed hash; wrong PINs lock the code for longer each time and tell HR.
Schedule Plan a weekly roster of shifts and days off, copy last week, publish it to staff, and let people mark when they are unavailable. Drafts stay hidden until published; a published shift or day off drives attendance and meals while leave and payroll keep the work week; a shift over leave or in an approved payroll month is refused; line managers schedule only their team.
Open shifts and swaps Post an open shift for staff to ask for, and let staff swap or give away a published shift with a colleague; your own shifts show on the calendar and in the calendar feed. The colleague accepts first, then both people's approvers approve; the swap is checked again at approval for leave, employment, clashes and approved payroll; unfinished swaps expire on the day.
Payroll Set salary structures, run a month, review, approve, export, email payslips (optionally with the PDF attached and locked with each person's own password); festival bonus runs. Maker and checker are different people; tax from the tenant's slabs; loan instalments deducted; a finalised run is read-only.
Meals Order daily meals and guests, set prices and vendors, generate and email monthly bills. Daily order cut-off in the tenant's time zone; bills computed from the month's orders and prices; payments tracked to zero.
Expenses and loans Claim with receipts, approve, pay directly or through payroll; request and approve loans with supporting documents. Receipts checked by content; nobody approves or pays their own claim unless the tenant allows a single admin.
Recruitment Open roles, move candidates through stages with their CVs, schedule interviews, collect feedback, make offers. Only members who can give feedback can sit on a panel; each interviewer gets their own list; candidate data purged after the retention window.
Performance and projects Run review cycles with goals, log timesheets against projects, plan the week. Ratings move from self to manager to finalised; a submitted week is locked.
Lifecycle Onboarding and offboarding checklists, resignations, exit interviews, letters from templates. Exited staff lose access after a grace period; letters render to PDF in Latin, Cyrillic, Greek, Vietnamese, Devanagari and Bengali script.
Directory Colleague list with search, org chart by manager or department with "Find me", work anniversaries and opt-in birthdays on the home page, a note to each manager on the day. Shows only name, role, team, branch, manager, joining date and work email; birthdays show day and month only and only for people who opted in; the chart loads one level at a time.
Calendar and events Month view of who is out, holidays and events, an agenda on phones, events for everyone, a department or a branch with going / maybe / not going and a reminder the day before, and a private calendar-app link. The link is stored as a hash, shows others only as "Out", answers 404 once the member, user or organisation is switched off, is replaced on a password change and is rate limited.
Skills, internal jobs and referrals A skills catalogue with manager validation, an internal job board with skill match and one-click apply, and referral bonuses that fall due after a qualifying period. Job descriptions use a safe Markdown subset with no HTML; applicants and referrers see only their own stages; rewards are salary data limited to the referrer and payroll.
Careers page A public list of open jobs per organisation where anyone applies with a PDF CV, landing as a Website candidate. Honeypot, signed form token with a minimum fill time, per-address, per-job and per-organisation limits, PDF header check, no email to applicants and the same answer for repeat emails.
Learning Courses with text, link, file and quiz lessons, assignments with due dates and renewals, PDF certificates with a verification code, external certifications and a training report. Quizzes graded on the server with answers never sent to the learner, attempt limits, certificate codes keyed to the server secret and checked per tenant, report limited to the viewer scope.
Pay reviews Review cycles with department budgets and a guideline raise; managers propose a percentage for their people and payroll applies the review as pending salary changes for finance to approve. Proposers see only salaries they may read and never their own row, the gross is worked out from the salary lines, and skipped people are listed with the reason.
Travel and per diem Trip requests with manager approval, an optional advance sent to finance as a salary advance, per diem rates by country or city, and expense claims settled against the advance. Approvers come from the leave chain and never decide their own trip, a claim links only to the claimant's own approved trip, and rates are one per place regardless of case.
Forms, checklists and tasks Forms built from up to 30 questions with photo, file and location answers, assigned to a department, a branch or everyone once, daily or weekly with reminders, plus ad-hoc tasks with due dates. Answers are checked on the server per question, each period is sent once, photos must really be images, and readers see only the people in their scope.
E-signature PDF documents signed in order by staff and outside people, offer letters accepted on signing, and a certificate of completion stored with its own hash next to the untouched original. Staff re-confirm their password, outside signers use a 10 minute email code with 3 sends and 5 tries that never reset, document SHA-256 shown before signing, every step audited.
1:1s and feedback Manager and employee 1:1s with shared agenda and actions that carry over, private notes, and feedback shown on the review for its period. Private notes are readable only by their author, never by HR, and are kept out of the audit log; feedback can be held back from its subject.
Kudos and announcement comments A kudos wall with company values, a monthly count by value and a home page card, plus reactions, comments and mentions on announcements. Comments and mentions stay inside the announcement's audience, are rate limited and can be hidden by HR with an audit trail; leavers show as "Former employee".
Surveys and suggestion box Pulse surveys with ratings, eNPS, choices and written answers for everyone, a department or a branch, two reminders, results by department or branch, and an anonymous suggestion box. Anonymous answers carry no person or time and are not audited; results show only after closing and for groups of at least five, and suggestions appear only in batches of five.
Modules Owners and HR admins turn optional parts of the app on or off per organisation. A module that is off leaves the menu and its pages and endpoints answer 404.
Workplace Announcements, policies with acknowledgement, assets, helpdesk tickets, notifications. A new policy version asks everyone to read it again; tickets can only be assigned to helpdesk agents.
Files and data Attach up to five PDFs or images to 15+ record types: leave, attendance corrections, loans, resignations, candidates, offers, salary changes, reviews and goals, projects, assets, announcements, tickets, cash meal bills, and education and experience entries (expense receipts stay on each claim line); add, replace or remove them while the record is open; import holidays, opening leave balances and assets from CSV; download each dataset as CSV from Settings. Files are checked by content and size and readable only by people who can see the record; imports are all-or-nothing with line-numbered errors and a template; data export needs a restricted permission plus the dataset's own permission at full scope, is capped at 366 days and 50,000 rows, and is audited.
Reports Headcount, leave, attendance, payroll, meals, expenses, recruitment, utilisation and a weekly digest; share with chosen colleagues. A report only shows rows the viewer's scope allows; shares respect the recipient's own access.
Search Press Ctrl K, / or the header button to find menu pages and records: employees by name, code or email, documents, letters, policies, announcements, tickets, expenses, assets, projects, openings, candidates and payroll runs; open any hit with the keyboard; recently opened pages come back first. Every module answers through the same visibility rule as its own page; confidential tickets match only by number and show no subject; each module query has an 800 ms limit inside a 2.5 s budget, so one slow module never blocks the rest; 60 searches a minute per user; trigram indexes keep contains-search fast.
Ask HR Ask on Home or the Ask HR page about your leave balances and requests, attendance, holidays, who is out, payslips and company policies; answers link to the pages they come from. Seven read-only lookups run with the asker's own access, each in its own short transaction; at most four rounds within 45 s; payslips only when payroll sharing is on; inactive policies and other tenants are never searched; links come only from server-issued sources; history stays in the browser, six turns and 8,000 characters at most; every round counts against the AI limits and budget.
Search inside files Words inside policy PDFs and candidate resumes (PDF, Word or image) are searchable, with the matching line shown under the hit; scanned PDFs and resume images are read by AI when it is on. Text-layer PDFs and Word files are read locally; PDFs parse in a separate thread with a 256 MB memory cap, a 50-page cap and a 20 s limit, and Word files unpack with a 20 MB cap; scans and images go to the company's AI and count against its budget; text is cleaned of control, direction and zero-width characters and capped at 200,000 characters; search keeps each module's visibility rule; a replaced policy file's text is deleted in the same transaction; failed reads back off and stop after three tries, and saving the AI settings retries the ones a key or quota problem stopped.
AI setup Settings → AI: turn AI on with consent, pick Google Gemini, OpenAI or Anthropic Claude, paste the company's API key, pick a model, set a monthly token budget, switch Ask HR, file reading and writing help on or off, test the connection and see this month's usage. Without a key the platform Gemini key is used when the operator allows it. Owner-only permission; a key is saved only after a successful test call, encrypted and bound to the organisation, and never shown, logged or audited beyond its last four characters; provider hosts are fixed and redirects refused; the model chain skips unlisted models and cools rate-limited ones; the budget is reserved atomically before each call, with per-person and per-organisation limits and a daily platform ceiling; no call runs while a database transaction is open; usage rows are kept for 13 months.
REST API Settings → API keys makes a read-only key for another system: employees, leave requests, attendance days, the published roster and events, at a chosen scope, for 30 days to a year. The API is described at /api/v1/openapi.json. Owner-only permission and a password check within the last 10 minutes; a key never reads more than its creator can today, so demoting or disabling the creator narrows or stops it; only the key's hash is stored; JSON only, Bearer keys, pages of at most 200 rows, 600 requests a minute per key, and no national ID, bank, tax or pay fields; creation, revocation and daily use are audited, and a password change revokes the person's keys.
Webhooks Settings → Webhooks sends a signed POST to up to 10 https endpoints when an employee is added or changed and when leave is requested, decided or cancelled. The body has the event name, ids and a time only. Same owner-only permission and password check; HMAC-SHA256 signature with a timestamp and a secret shown once; the event commits with the change; 8 tries over about two days, and 50 failures in a row turn the endpoint off and notify its managers; only public addresses on port 443, every resolved address checked, no redirects, 5 second limit, 64 KB reply cap.
Attendance devices Settings → Attendance devices adds a fingerprint or card reader with its own key. It posts up to 500 punches at a time to /api/v1/punches, matched by device user ID or employee code, and each punch comes back accepted, repeated or refused with a reason. Everyone's-attendance permission and a password check; the key is shown once and stored as a hash; it can only post punches, and API keys cannot; 60 requests a minute per device, 256 KB per request, punches older than 31 days or ahead of the clock refused; punches in a month already paid are kept and listed for HR to check.
Company sign-in Settings → Company sign-in connects Google Workspace or Microsoft Entra. People link their company account once from Account → Security or accept an invitation with it, and the owner can require it for everyone else. Owner-only and a password check; only domains proven by a DNS TXT record, each owned by one organisation; matched by the provider's account ID, never by email; PKCE, nonce and a browser-bound state kept 10 minutes; a company sign-in opens that organisation only and cannot change passwords or 2FA; the owner keeps password and 2FA sign-in.
Provisioning (SCIM) Entra or Okta adds and deactivates people through SCIM 2.0 with a token from Settings → Company sign-in. Token shown once, stored hashed, replaceable and revocable; people added in verified domains only; existing accounts untouched and no names returned; owners left alone; it never turns back on someone HR or an exit turned off.
AI file reading and writing help Read receipt fills an expense row, Read CV fills a new candidate, Read document fills a certificate's title and expiry; Draft with AI writes an announcement or a job description and Suggest a reply drafts a helpdesk answer. Everything is a suggestion the person checks and submits. Needs the page's permission and the AI feature switch; files are type-sniffed, capped at 10 MB (5 MB images on Anthropic) and never stored; identity and contract documents, confidential tickets and internal notes are never sent; model output is parsed as data and checked again by the normal form rules; a receipt in another currency leaves the amount blank; file reading has its own per-person limit.

Tests

  • 287 unit tests with Vitest for money, dates, tax, parsing and PDFs.
  • 363 integration tests against a real Postgres, Redis and MinIO, including cross-tenant and scope attacks; a shared leak helper checks every read with own, team, department, company and other-tenant viewers.
  • 75 Playwright end-to-end tests that drive the built app, read the emails it sends and check phone layouts.

Pipeline

  • CI brings up the Compose services, then runs type checks, lint, unit, integration and e2e tests.
  • Every phase ended with an adversarial review whose findings were reproduced, fixed with a failing test first, and re-run.
